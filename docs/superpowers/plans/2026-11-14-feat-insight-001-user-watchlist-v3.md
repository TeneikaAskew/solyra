# Per-user watchlist served by the stocks API (solyra, v3) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Every task cites a spec section and the done_when item it advances (done_when[0] is the first item).

**Goal:** The Watchlist tab shows the stocks default list read-only and the signed-in user's own list with add and remove, both served by the stocks API same-origin, ranks both together through `extras`, and the combobox auto-add writes to the user's list; nothing in solyra touches Supabase or the two old stocks write routes.

**Architecture:** `src/hooks/useUserWatchlist.ts` wraps `GET`, `POST /api/me/watchlist` and `DELETE /api/me/watchlist/{ticker}` with TanStack Query through the ordinary relative `fetch` (`src/lib/authedFetch.ts` signs every `/api` call with the Firebase ID token); `useDefaultWatchlist` wraps `GET /api/insights/watchlist/default`; `useWatchlist` gains `extras` in its query key; two new sections in `WatchlistPanel`; the combobox calls the add mutation; the old write hooks are deleted; types come from the regenerated OpenAPI after `npm run contract:sync`; Playwright covers it hermetically with `page.route`.

**Tech Stack:** React 19, TanStack Query, Vitest (colocated), Playwright (hermetic, own Vite on :5199), the vendored stocks OpenAPI through `npm run contract:sync`.

**Spec:** `docs/superpowers/specs/2026-11-14-feat-insight-001-user-watchlist-v3.md` (approved; supersedes v2).

**Cross-repo order:** Task 1 needs the stocks user-watchlist API PR (spec `2026-11-14-feat-insight-001-user-watchlist-api.md`) and lock stage A on stocks main; the branch opens after both merge, so every later task compiles against generated types and `src/mocks/contract.test.ts` stays green throughout.

## Global Constraints

- No call to `POST /api/insights/watchlist/add` or `DELETE /api/insights/watchlist/{ticker}` remains under `src/` or `tests/` after Task 5 (done_when[2]).
- Identity is the Firebase ID token the fetch wrapper attaches; the hooks send no `apikey`, no custom auth header and no body field naming the user (§ Hooks).
- Rule 4: no fabricated empty list. Signed out is its own state (the query is disabled); a non-OK response throws `Error(detail)` and renders as the error state with the API's detail verbatim.
- Copy, verbatim: section title `Managed in Discord`; `data arrives after tonight's fetch`; `no data for this symbol`; `Nothing yet; add a ticker`; `Sign in to keep a watchlist`; combobox notice `Added to your watchlist`.
- `dataStateCopy` reads `last_daily_bar` and `added_at` only; the ingest window boundary is the most recent elapsed 00:30 `America/New_York` instant, computed with the named zone, never a fixed offset.
- No file this plan touches imports from `src/integrations/supabase` or names a Supabase URL, key, project or function (done_when[4]).
- No em or en dashes in code, copy or docs.

## Review Focus

1. A 401 from `/api/me/watchlist` (token expired between render and request) is the signed-out state, not an error toast with a stale list. Pinned in Task 2.
2. `extras` changes after the first ranking: the ranked query refetches because the normalized list is in its key; a membership that resolves to the same set does not refetch. Pinned in Task 3.
3. `dataStateCopy` at 00:29 and 00:31 ET and on the DST days 2026-03-08 and 2026-11-01: the boundary moves with the named zone. Pinned in Task 4.
4. The combobox's notice never promises ingest; it shows `Added to your watchlist` plus the row's data state. Pinned in Task 5.
5. The contract test validates the `POST /api/me/watchlist` request sample against the stocks schema (`ticker`, `source` enum), so a renamed field fails here before it fails in production. Pinned in Task 1.
