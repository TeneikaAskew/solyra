# Research evidence completeness and safe freshness/replay

## Approval and scope

Approved repair scope: [GCP repair review](https://chatgpt.com/space/page_531ea2540b4c8191a4e5267eb24f1b89). On 2026-10-12 the user directed, “Execute the plan with test driven development.” This spec records that previously approved repair scope; it does not claim fresh approval of additional features. Approval covers implementation and tests of these repairs, not an assertion that a provider credential or unverified endpoint works. Spec publication precedes implementation.

## Problem

`supabase/functions/insights-research/index.ts::gather` currently omits the existing stocks gamma-level and report-history endpoints. Its `valueAsOf` misses quote `timestamp`; a null parsed timestamp is classified current. `clipReplay` only filters array entries: a root report with `analysis_date=2026-10-09` survives an October 8 cutoff, as do nested untimed derived observations. The prompt then calls any available live-quote payload the authoritative current price even though the endpoint uses AV's default EOD contract. Repeated HTTP 200 responses can make incomplete or stale upstream sources appear healthy.

Evidence is the approved review and `work/gcp-review/consumer-reproduction.json`, production SQL/schema evidence and API handler inspection (protected endpoint probes returned 403) and inspected source at solyra `da584ca45403183c741231d95511a0f5747d333f`. Reproduce these shapes in committed redacted fixtures. Catalog row: `FEAT-INSIGHT-001 | AI insights | LLM per-ticker reports + chat`, with `/api/insights` and Lovable research functions. Existing approved workspace specs cover UI composition; this is a focused repair of the evidence contract and does not supersede or widen those specs. No verified solyra issue IDs were supplied; `issues: []`. stocks#1217 is cross-repository context, not a solyra closure claim.

## Non-goals

No duplicated financial math, new market-data provider, frontend-computed gamma, invented API parameter, new research product, model change, rebrand or redesign. stocks remains the financial source of truth; Lovable owns orchestration and research-session persistence. Do not synthesize a replay-safe result by recursively retaining everything without a timestamp. Do not silently reclassify EOD as live or mutate a frozen historical session with new evidence.

## Approaches considered

1. Add two fetches to the existing generic parser: rejected; it retains the faulty freshness/replay contract.
2. Recompute financial evidence in the edge function: rejected; it creates a second financial engine.
3. Typed endpoint adapters with explicit source health, upstream temporal guarantees and conservative exclusions: selected.

## Design

### A. Evidence module and endpoint manifest

Extract orchestration-safe helpers from `supabase/functions/insights-research/index.ts` into `supabase/functions/insights-research/evidence.ts`, importable without starting Deno. Preserve the function's authenticated streaming/session interface. Define `EvidenceSource` with stable ID/type/label/path, `observedAt`, `availableAt`, `fetchedAt`, `freshness` (`current|stale|unavailable` for storage compatibility), `sourceStatus` (the full upstream state), reason, temporalGuarantee, entitlement, coverage, payload and hash. Unknown availability does not imply current. Existing `asOf` remains an alias for source observation time for old readers; fetching time is never its substitute.

`buildEvidenceRequests(ticker: string, mode: 'live'|'replay', cutoff: string|null): EvidenceRequest[]` uses the existing report, brief, playbook, signals, catalysts and price-history routes and adds **gamma** `/api/options/{ticker}/{date}/levels` (the registered stocks route is `/api/options/{ticker}/{date_str}/levels`; the manifest test pins it) and **report history** `/api/insights/report/{ticker}/history?versions=true&limit=20`. Stable existing citation IDs S1–S7 remain unchanged; gamma uses S8, report history S9. Live quote remains live-mode only. Use the existing `/api/options/dates/{ticker}` endpoint to choose a last eligible gamma date if needed, bounded to one discovery request; date-only EOD is unavailable before its session completion/availability, never future-filled. At most 10 HTTP requests per new live question, 9 replay; same-origin stocks paths only, auth forwarded without logging it. Use an AbortController deadline of 10 seconds/source and concurrency at most 4.

Do not assume that adding `as_of` makes an endpoint honor it. Maintain a per-route adapter contract: accepted query keys, response shape, timestamp fields, whether source availability/revisions are returned, whether the endpoint proves point-in-time derivation. Report-history summaries are bounded to 20; do not fetch every full report. Gamma source returns stored/server-computed levels and provenance, never an edge-computed value. Report history preserves at least two distinct eligible versions when available, with report/run IDs and observation/availability clocks, so the existing evidence UI can compare their sourced decision fields without blending them; fewer than two is an explicit comparison-unavailable state. HTTP failures, unknown envelope shapes, empty data and source status partial/stale/unavailable appear as reasoned source objects rather than disappearing from the manifest.

### B. Freshness and price semantics

`normalizeEvidence(request: EvidenceRequest, payload: unknown, context: EvidenceContext): EvidenceSource` consumes upstream source receipt/health from the stocks data-integrity spec. `EvidenceContext` has `mode`, `cutoff` and injected `now` (all valid timezone-aware instants); it never uses hidden wall-clock in tests. Backend freshness is authoritative when accompanied by valid clocks and contract metadata; contradictory or invalid metadata degrades safely. Remove the universal seven-day heuristic. If a legacy source lacks the required cadence/clock/proof, return unavailable for current/replay claims with a specific reason; the UI may retain the dated historical snapshot as such without promoting it to a current claim.

Quote adapters explicitly parse `timestamp` only when it is a valid timezone-aware instant; date-only `latest_trading_day` carries day precision. Preserve requested/effective entitlement and source session. EOD can be the latest known closing snapshot on a weekend; it is never the authoritative live/intraday price. `selectReferencePrice(evidence: EvidenceSource[]): ReferencePrice | null` uses only a backend-confirmed current quote with exact timestamp and verified matching entitlement/session, otherwise returns null and names the dated reference separately. Distinguish report headline price, premarket snapshot and latest quote in prompt and UI. Update the model instruction that currently calls any `live_quote` authoritative. Do not derive prices, confidence, gamma or trading signals in TypeScript.

### C. Replay eligibility

`filterReplayEvidence(source: EvidenceSource, cutoff: string): EvidenceSource` acts on typed root envelopes as well as nested arrays. Realized facts require `observedAt <= cutoff` and version `availableAt <= cutoff`; later revisions are excluded even if their event date is earlier. Derived root objects require the upstream production replay/point-in-time guarantee plus eligible dependencies; a top-level date alone cannot prove all nested inputs were known. Inherited source clocks are permitted only where the documented schema guarantees they cover every child. Untimed children cannot escape through a generic recursion.

Scheduled future events may remain if the **schedule record** was known by cutoff; release actuals and revised fields need separate version clocks and are excluded until available. Date-only report/calendar fields are not interpreted as midnight UTC to bypass an intraday cutoff. Use production backend as-of support only when verified; for brief/playbook/history or any route without a provable temporal contract, emit `unavailable: replay_not_supported` or `availability_unproven`, and do not send its payload to the model. This exclusion supplies the negative safety boundary; it does not by itself complete gate 5. The positive persisted macro and immutable report-version paths in data spec §M/report spec §F must also pass through the actual research adapter. Current live quote is never requested in replay. Known report `run_kind=live` is not eligible simply because its `as_of` precedes cutoff if it uses later source observations; require dependency proof.

The exact reproduction `{analysis_date:'2026-10-09', price:277.57, daily_indicators:{close:278.94}}` at cutoff `2026-10-08T20:00:00Z` must produce unavailable/null payload. Shared fixture cases with stocks cover same-day later timestamps, timestamp offsets, DST boundary, revised macro actual, repaired October 8 options discovered October 12 and future scheduled release known before cutoff. These are adapter tests of production API contracts, not independent financial replay calculations.

### D. Persistence, citations and UI

Wire `gatherEvidence(requests: EvidenceRequest[], context: EvidenceContext, deps: EvidenceDependencies): Promise<EvidenceSource[]>` into the existing handler. Dependency injection supplies fetch/clock/hash for hermetic tests. Persist full receipt fields and selected immutable payload in the existing source `metadata` JSON; no financial schema duplication. Compute hashes from the actual selected model payload and canonical metadata, after explicit size bounds; expose truncation/coverage when clipping lists. Keep each source ≤45,000 serialized characters and the total selected evidence ≤160,000 characters, with an explicit omission reason when capacity is exhausted. At most 20 report history entries and existing bounded signals. Never splice arbitrary JSON text.

A follow-up in a frozen session reuses its original snapshots and recomputes eligibility against the same cutoff; it does not fetch newer data or replace old availability times. Old saved sources without metadata are legacy/unproven and cannot be upgraded to current by restoration. Keep owner checks and ticker/mode/cutoff binding; cross-owner read or follow-up remains rejected. Citation validation permits only payload-bearing eligible sources, including explicitly dated stale snapshots when used as historical context; unavailable/failed/partial-without-qualified-data sources cannot support financial claims. Partial data needs its coverage caveat with the cited claim. Prompt unknowns list failed/excluded sources. A source failure must not erase healthy sources or the last completed answer.

Update the existing research evidence panel/types/hooks and the bounded null/status compatibility of all direct report/persona consumers, including `src/components/insights/ReportCards.tsx` and `src/routes/InsightsPage.tsx`, plus pending-plan presentation in `src/routes/InsightsLovablePage.tsx` and `src/hooks/useInsightsLovable.ts` with `src/types/insightsLovable.ts`/`src/types/insights.ts`; reuse `src/components/insights/redesign/decision.ts` where the existing shared decision display consumes nullable plan fields. Evidence labels show source/session/time/status; optional metadata has safe legacy defaults. Render nullable plans from the stocks report-consistency spec as pending or unavailable without copying structural candidate prices into entry fields. Existing workflow navigation and session IDs stay unchanged. `ReportCards.tsx` must not dereference a nullable headline/persona entry or multiply null confidence into 0%; display unavailable conviction/confidence and pending/invalidated states explicitly. Test these paths on `/insights`, and the shared report rendering on `/insights-lovable` and `/ai-insights-lovable`, including unchanged legacy complete reports. These are compatibility repairs, not a redesign.

### E. Acceptance, capacity and rollout

Extend `vite.config.ts`'s explicit test include with `supabase/functions/insights-research/*.test.ts` (currently excluded), without changing existing globs. Extracted helpers are tested with `VITE_NO_BACKEND=1 npx vitest run supabase/functions/insights-research/evidence.test.ts supabase/functions/insights-research/handler.test.ts`; the function continues to import its Deno/npm dependencies only from runtime entrypoints. Run `npm run build`, relevant existing insight suites and `npm run e2e -- tests/insights-lovable/research-evidence.spec.ts` using the repository's hermetic mocked API contract. Browser tests call the actual shared evidence helpers/handler with injected HTTP fixtures or consume captured output from that tested handler; tests that only hard-code a successful UI fixture cannot establish gatherer correctness. Save explicit `page.screenshot` artifacts through `testInfo.outputPath(...)` for healthy, degraded, replay and pending states.

Capacity: no Cloud Run job in this repository, so deployment PR's Cloud Run Capacity section is `n/a: edge research orchestration and browser only; no scheduled workload`. Edge request bound is 10×45,000 characters ≤450 KB fetched before reduction (UTF-8 may be up to 4×; enforce byte bounds during read to cap ≤1.8 MB), selected model evidence ≤160,000 characters (a size bound, not a promised token count), concurrency 4, at most three 10-second waves ≈30 s gather ceiling. At most one existing model request per question, one bulk source insert ≤9 rows, and existing session/message/run writes. Added gamma/history are two payload requests plus at most one discovery request; no per-history-row fetches. Token/cost estimation must use the configured model's actual tokenizer/pricing in implementation evidence; do not invent model prices. I/O-shape tests prove bounds and abort behavior. Restore/follow-up has zero new evidence HTTP calls.

Runbook lists endpoint shape/version fixtures, compatibility with pre-metadata stocks responses, excluded replay routes, logged counts/durations/exclusion reasons without tokens or private prompt bodies, edge-function rollback and browser checks after deployment. Publish stocks source contract before claiming new metadata current in solyra; missing metadata degrades safely, but nullable report responses require the tolerant UI-first deployment sequence in report spec §G; deployment in either order is not safe for the existing report cards. Update only the FEAT-INSIGHT-001 catalog status/review date/PR; docs audit has no new findings versus origin/main. This spec does not authorize deployment from the documentation branch.

### F. Producer/consumer handshake and positive historical proof (review C2–C4)

Implement the route/section matrix in stocks data spec §M and immutable history in report spec §F as a shared versioned JSON contract fixture. Research does not invent the `temporal_proof` object. Consume `status`, `data_cutoff`, observed/available clocks, immutable `version_id`, payload hash, covered dependencies, excluded sections/reasons and `all_payload_fields_covered`; reject proven claims whose payload hash or field coverage is inconsistent. Backend source versions establish financial availability; the research capture/fetch clock is separate.

For S9, add `versions=true` and in replay the encoded aware `as_of` to the existing history request **before** the server applies its limit. Each item carries `id=history:<id>`, run/current pointer IDs, data/generated/available times, generation_kind/operation_kind, temporal proof and bounded decision projection. Compare two versions from the same ticker/cutoff without N+1 calls. A current-cache UUID and history version ID are visibly different records. S1 replay requests the production `as_of` selector, which now reads proven immutable versions; an explicit version is opened through existing `/api/insights/reports/history:<id>?as_of=...` when selected by the user, not automatically fetched once per history row.

S5 adds aware `as_of` for replay, consumes versioned macro actual/schedule fields, and preserves `etf_mappings` from the existing catalyst envelope with source holdings date, source/fetch/availability clocks, version/hash, coverage and reason. Unknown holdings/date or partial mapping remains an unknown/partial source in both prompt and evidence panel; no inference of ETF constituents, no added request. S8 may pass the producer's verified optional `as_of` on the levels endpoint and uses its chain/rate dependency proof; unknown availability never becomes inferred eligibility. S2/S3/S4/S6 (brief/playbook/signals/price history) remain unsupported in replay unless their existing route contract independently proves all fields, so they return reason-only source objects. S7 current quote is omitted in replay.

The positive acceptance fixture must originate from actual stocks production writers/SQL/handlers against isolated PostgreSQL, not a hand-built proven envelope: two IWM report attempts with the same `2026-10-08T13:00:00Z` data cutoff and distinct immutable versions available at 14:00 and 15:00, plus an October 9 macro actual version known before a later October 12 cutoff and a later revision after that cutoff. Import the exact JSON/hash into the real evidence helper and handler. At 16:00 both report versions reach comparison/citations; 14:30 admits only the first; adding twenty-one later history versions must not hide that first result because server predicates apply before LIMIT. Macro actual and ETF mapping metadata reach the model source payload/panel; post-cutoff revision and unversioned nested data do not. The fixture's immutable payload/receipt proof is checked against the contract version, so a fake positive response cannot satisfy the test by itself. Preserve separate operational provider-unavailable status where no real dated holdings response was captured.

The bounded UI compatibility slice in Task 6 is deployed before the backend nullable-response PR merges/deploys. Its tests render legacy complete, pending, invalidated, unavailable and null confidence/conviction reports through the real existing cards. Owner staging verification records the tolerant consumer commit; only then can backend null publication be enabled. Backward-compatible research gathering against pre-metadata responses can ship safely earlier with explicit unavailable sources. This dependency is part of the three-contract delivery sequence, not an additional user approval request.

## Risks

The strict replay policy will expose previously hidden unsupported sources; the user sees explicit unknowns, not fabricated history. Two extra evidence types can increase latency/context size; request, payload and model-input limits are tested. Old frozen sessions lack receipt metadata; they remain readable as historical artifacts but cannot be promoted into current evidence. Browser mocks can miss backend defects; separate stocks API tests and shared fixtures prove the provider contract, and the owner posts deployed-site checks after staging deployment.
