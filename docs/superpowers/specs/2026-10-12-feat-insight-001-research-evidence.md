## Problem

`supabase/functions/insights-research/index.ts::gather` currently omits the existing stocks gamma-level and report-history endpoints. Its `valueAsOf` misses quote `timestamp`; a null parsed timestamp is classified current. `clipReplay` only filters array entries: a root report with `analysis_date=2026-10-09` survives an October 8 cutoff, as do nested untimed derived observations. The prompt then calls any available live-quote payload the authoritative current price even though the endpoint uses AV's default EOD contract. Repeated HTTP 200 responses can make incomplete or stale upstream sources appear healthy.

Evidence is the approved review and `work/gcp-review/consumer-reproduction.json`, production SQL/schema evidence and API handler inspection (protected endpoint probes returned 403) and inspected source at solyra `da584ca45403183c741231d95511a0f5747d333f`. Reproduce these shapes in committed redacted fixtures. Catalog row: `FEAT-INSIGHT-001 | AI insights | LLM per-ticker reports + chat`, with `/api/insights` and Lovable research functions. Existing approved workspace specs cover UI composition; this is a focused repair of the evidence contract and does not supersede or widen those specs. No verified solyra issue IDs were supplied; `issues: []`. stocks#1217 is cross-repository context, not a solyra closure claim.

## Non-goals

No duplicated financial math, new market-data provider, frontend-computed gamma, invented API parameter, new research product, model change, rebrand or redesign. stocks remains the financial source of truth; Lovable owns orchestration and research-session persistence. Do not synthesize a replay-safe result by recursively retaining everything without a timestamp. Do not silently reclassify EOD as live or mutate a frozen historical session with new evidence.

## Approaches considered

1. Add two fetches to the existing generic parser: rejected; it retains the faulty freshness/replay contract.
2. Recompute financial evidence in the edge function: rejected; it creates a second financial engine.
3. Typed endpoint adapters with explicit source health, upstream temporal guarantees and conservative exclusions: selected.

## Design

### A. Evidence module and endpoint manifest

Extract orchestration-safe helpers from `supabase/functions/insights-research/index.ts` into `supabase/functions/insights-research/evidence.ts`, importable without starting Deno. Preserve the function's authenticated streaming/session interface. Define `EvidenceSource` with stable ID/type/label/path, `observedAt`, `availableAt`, `producerFetchedAt`, `researchCapturedAt`, `freshness` (`current|stale|unavailable` for storage compatibility), `sourceStatus` (the full upstream state), reason, temporalGuarantee, entitlement, coverage, payload, `producer_integrity_hash`, `selected_snapshot_hash` and `integrity_version`. Legacy `hash` is an optional alias of selected_snapshot_hash only on new proven metadata; an old hash alone establishes no proof. Unknown availability does not imply current. Existing `asOf` remains an alias for source observation time for old readers; fetching time is never its substitute. `producerFetchedAt` is the upstream producer-hashed temporal_metadata.fetched_at (or null/unproven); `researchCapturedAt` is the actual research response-capture instant, fixed on first capture. Optional legacy `fetchedAt` aliases researchCapturedAt only and is excluded from hash inputs to avoid ambiguity. Never map research time into producer fetched_at or change either clock on restore. For typed S9 collections, producer clocks live on each item; a null collection-level producer clock does not override child clocks or create a financial availability claim.

`buildEvidenceRequests(ticker: string, mode: 'live'|'replay', cutoff: string|null): EvidenceRequest[]` uses the existing report, brief, playbook, signals, catalysts and price-history routes and adds **gamma** `/api/options/{ticker}/{date}/levels` (the registered stocks route is `/api/options/{ticker}/{date_str}/levels`; the manifest test pins it) and **report history** `/api/insights/report/{ticker}/history?versions=true&limit=20`. Stable existing citation IDs S1–S7 remain unchanged; gamma uses S8, report history S9. Live quote remains live-mode only. Use the existing `/api/options/dates/{ticker}` endpoint to choose a last eligible gamma date if needed, bounded to one discovery request; date-only EOD is unavailable before its session completion/availability, never future-filled. At most 10 HTTP requests per new live question, 9 replay; same-origin stocks paths only, the verified incoming user bearer Authorization forwarded without logging or persisting it. Handler tests use a fake stocks origin that rejects missing/wrong Authorization for every route, including gamma-date discovery/S8/S9; signed-out or rejected identity must stop before evidence/model requests. A stocks401/403 remains explicit source failure and cannot be retried anonymously or with service credentials. The request bound is evidence HTTP only; existing identity validation is counted separately and preserved. Use an AbortController deadline of 10 seconds/source and concurrency at most 4, including body streaming/parse rather than headers alone. Read at most180000 UTF-8 bytes/source and1800000 aggregate raw bytes; stop/cancel an oversized or hanging stream before buffering it whole. An over-limit source is explicit unavailable/truncated as the typed adapter permits, never silently accepted from incomplete JSON.

Do not assume that adding `as_of` makes an endpoint honor it. Maintain a per-route adapter contract: accepted query keys, response shape, timestamp fields, whether source availability/revisions are returned, whether the endpoint proves point-in-time derivation. Report-history summaries are bounded to 20; do not fetch every full report. Gamma source returns stored/server-computed levels and provenance, never an edge-computed value. Report history preserves at least two distinct eligible versions when available, with report/run IDs and observation/availability clocks, so the existing evidence UI can compare their sourced decision fields without blending them; fewer than two is an explicit comparison-unavailable state. HTTP failures, unknown envelope shapes, empty data and source status partial/stale/unavailable appear as reasoned source objects rather than disappearing from the manifest.

### B. Freshness and price semantics

`normalizeEvidence(request: EvidenceRequest, payload: unknown, context: EvidenceContext): EvidenceSource` consumes upstream source receipt/health from the stocks data-integrity spec. `EvidenceContext` has `mode`, `cutoff` and injected `now` (all valid timezone-aware instants); it never uses hidden wall-clock in tests. Backend freshness is authoritative when accompanied by valid clocks and contract metadata; contradictory or invalid metadata degrades safely. Remove the universal seven-day heuristic. If a legacy source lacks the required cadence/clock/proof, return unavailable for current/replay claims with a specific reason; the UI may retain the dated historical snapshot as such without promoting it to a current claim.

Quote adapters explicitly parse `timestamp` only when it is a valid timezone-aware instant; date-only `latest_trading_day` carries day precision. Preserve requested/effective entitlement and source session. EOD can be the latest known closing snapshot on a weekend; it is never the authoritative live/intraday price. `selectReferencePrice(evidence: EvidenceSource[]): ReferencePriceSelection` returns the discriminated union `{status:'current', price:ReferencePrice, reason:null, datedReference:DatedReference|null}` or `{status:'unavailable', price:null, reason:PriceUnavailableReason, datedReference:DatedReference|null}`. It uses only a backend-confirmed current quote with exact timestamp and verified matching entitlement/session for current price. A sourced EOD/headline/premarket historical value may remain in datedReference with source ID/version, observed time/precision and session; absent/unverified values remain null. Reasons include missing_timestamp, invalid_timestamp, eod_only, entitlement_mismatch, session_mismatch, upstream_health_conflict and no_eligible_quote; define deterministic precedence for multiple failures and test each independently. Callers consume this value directly, with no undocumented side channel or module-global last error. A valid timestamp is insufficient: table-driven tests individually mismatch requested versus effective entitlement, requested versus effective session, and current quote metadata versus stale/partial/failed upstream health; each returns status=unavailable, price=null and a specific reason in the same result. Keep a valid-clock/matching-session/current-health positive control and distinguish it from an EOD dated reference. Distinguish report headline price, premarket snapshot and latest quote in prompt and UI. Update the model instruction that currently calls any `live_quote` authoritative. Do not derive prices, confidence, gamma or trading signals in TypeScript.

### C. Replay eligibility

`filterReplayEvidence(source: EvidenceSource, cutoff: string): EvidenceSource` acts on typed root envelopes as well as nested arrays. Realized facts require `observedAt <= cutoff` and version `availableAt <= cutoff`; later revisions are excluded even if their event date is earlier. Derived root objects require the upstream production replay/point-in-time guarantee plus eligible dependencies; a top-level date alone cannot prove all nested inputs were known. Inherited source clocks are permitted only where the documented schema guarantees they cover every child. Untimed children cannot escape through a generic recursion.

Scheduled future events may remain if the **schedule record** was known by cutoff; release actuals and revised fields need separate version clocks and are excluded until available. Date-only report/calendar fields are not interpreted as midnight UTC to bypass an intraday cutoff. Use production backend as-of support only when verified; for brief/playbook/history or any route without a provable temporal contract, emit `unavailable: replay_not_supported` or `availability_unproven`, and do not send its payload to the model. This exclusion supplies the negative safety boundary; it does not by itself complete gate 5. The positive persisted macro and immutable report-version paths in data spec §M/report spec §F must also pass through the actual research adapter. Current live quote is never requested in replay. Known report `run_kind=live` is not eligible simply because its `as_of` precedes cutoff if it uses later source observations; require dependency proof.

The exact reproduction `{analysis_date:'2026-10-09', price:277.57, daily_indicators:{close:278.94}}` at cutoff `2026-10-08T20:00:00Z` must produce unavailable/null payload. Shared fixture cases with stocks cover same-day later timestamps, timestamp offsets, DST boundary, revised macro actual, repaired October 8 options discovered October 12 and future scheduled release known before cutoff. These are adapter tests of production API contracts, not independent financial replay calculations.

### G. Two integrity domains and shared canonicalization

Use `integrity_version="rfc8785-sha256-v1"`: SHA-256 of UTF-8 bytes from RFC8785 JSON Canonicalization Scheme (JCS), hex lowercase. Python producers and TypeScript consumers use conforming implementations and the same committed vectors; Python json.dumps(sort_keys=True) is not sufficient for JCS numbers/key ordering. Reject non-JSON/nonfinite numbers, duplicate JSON keys and unpaired surrogates; identifiers beyond IEEE754-safe integers are strings. Do not apply Unicode normalization. Vectors cover reordered keys, nested arrays, astral/combining Unicode, negative zero and exponent/round-trip floating-point formatting.

`producer_integrity_hash` covers the exact producer-returned integrity input **before** research projection/clipping: `{contract_version, version_id, payload, temporal_metadata}`. For bounded history each item gets its own input/digest over its returned decision projection, not an unseen full report; the server validates the underlying persisted payload_hash and records its source version/hash dependency. `temporal_metadata` has exactly `source`, `status`, `reason`, `observed_at`, `available_at`, `fetched_at`, `data_cutoff`, `coverage`, `entitlement`, `session`, `dependencies`, `excluded_sections` and `all_payload_fields_covered` (use explicit null/empty collections where absent); immutable dependency version/payload hashes are included, while the envelope's own producer_integrity_hash and selected-snapshot hashes are excluded; producer_digest/input are outside payload to avoid recursion. The API schema defines this input explicitly and both implementations reconstruct it identically. Historical `payload_hash` remains the hash of the original persisted payload, raw_payload_hash remains raw receipt bytes; neither is substituted for the returned projection digest. Legacy inputs without the new integrity contract are unproven for replay. A hash proves byte/content consistency, not provenance by itself: the production SQL/writer tests and clocks still establish availability.

`selected_snapshot_hash` covers `{integrity_version, source_id, mode, cutoff, producer_integrity_hash, selected_payload, receipt_metadata}` after the exact model selection/projection/truncation. `receipt_metadata` is the versioned selected metadata schema: observedAt/availableAt/producerFetchedAt/researchCapturedAt, sourceStatus/freshness/reason, entitlement/session, coverage, temporalGuarantee, version IDs and truncation/exclusions; omit digest aliases and UI/request-ephemeral fields. Persist this complete selected object and hash atomically with source metadata. Follow-up verifies/reuses the stored object and hash; neither producerFetchedAt nor researchCapturedAt is refreshed. A valid producer digest remains unchanged when research clips a list, while selected_snapshot_hash changes; changing selected content without its hash fails restoration. Changing producer content or proof without recomputing its digest fails preselection validation. Persist the bounded original returned producer integrity input and digest alongside the selected snapshot, outside selected model payload; clipping makes the original digest impossible to recompute from selected content alone. Frozen restore independently verifies original producer input/digest (and all S9 item/collection digests), then the selected object/digest and its binding to that producer digest, before any model call. Mandatory independent mutations alter original producer payload, temporal proof, digest, selected payload, selected receipt and selected digest. Each must fail restoration with integrity_mismatch, zero evidence fetches, zero Gateway attempts and no replacement of the previous completed answer/source pair. Positive clipped restore preserves both original producer digest and exact selected evidence. These are integrity checks against stored hashes, not authentication against an attacker replacing both data and all hashes; owner protections remain separate. Tests assert those separate failures and a valid clipped/projection case, plus identical Python/TypeScript JCS bytes/digests.

R3 requires producer test evidence and artifact identity, not only a consumer unit test. Data `tests/integration/test_data_integrity_acceptance.py` exports `tests/fixtures/data_integrity/consumer_contract.json`; report `tests/integration/test_insight_report_acceptance.py` exports `tests/fixtures/data_integrity/report_version_contract.json`. Each exporter writes a matching manifest with producer repository/commit, exact test node IDs and passed run reference, schema/contract version, raw artifact SHA-256, JCS vector digest set and per-response producer_integrity_hash. Verify underlying stored payload hashes and SQL availability predicates before export; include21 later versions to prove filtering before LIMIT. Copy the exact artifacts/manifests to `supabase/functions/insights-research/fixtures/`, verify byte hashes before tests and link both producer test runs in the research PR's R3 evidence. A hand-edited positive fixture or passing Vitest alone cannot satisfy R3. Producer tests can run on a reviewed backend implementation commit before backend merge; tolerant UI publication therefore need not wait for nullable backend deployment, avoiding the I7 cycle.

### S9 collection integrity and separate capture clocks

The report producer owns the S9 aggregate on the existing opt-in `versions=true` history response; default legacy history shape is unchanged and DATA/research consume this contract without another endpoint or request. Return a typed collection integrity input `{contract_version:"report-history-list-v1", version_id:null, payload:{selection, items}, temporal_metadata}` plus its `producer_integrity_hash` outside the input. `selection` has exactly ticker, requested_cutoff (aware ISO or null), generation_kind, limit and order (`available_at_desc,id_desc`). `items` is the complete ordered returned list (at most20), each item containing its existing contract_version, version_id, bounded payload, temporal_metadata and individual producer_integrity_hash. The collection digest is SHA256/JCS of this exact input, including item order, projections, proofs and individual digests; it is the **single S9 EvidenceSource.producer_integrity_hash**. Item digests remain separately accessible and are verified before the aggregate. Duplicate version IDs, wrong item order or mismatched selection are rejected. A digest is a content-integrity check, not a cryptographic signature or authenticity claim.

Collection temporal_metadata uses the same named fields: source=report_history; status/reason describe the bounded listing; coverage records returned_count and the server selection; dependencies is the ordered list of each immutable version ID, stored payload_hash and item producer_integrity_hash; excluded_sections lists server exclusions; all_payload_fields_covered asserts the typed collection and every included item's proof were validated. Collection-level observed_at/available_at/fetched_at/data_cutoff and entitlement/session are explicit null when not meaningful. This typed listing exception does not invent aggregate financial clocks: every item independently carries and passes its report availability, own data_cutoff and covered dependency clocks. It cannot make a child eligible through a null or newer collection clock. Empty lists still have a deterministic collection digest and explicit no-comparison state; one item is historical evidence, not a two-version comparison.

Research verifies the complete returned collection before filtering/clipping, retains that bounded original integrity input, and uses its unchanged collection digest in the selected_snapshot_hash input. Selected item IDs/order/projections and exclusion/truncation metadata are covered by the separate selected snapshot digest. Filtering two versions to one or zero, or clipping a projection, changes the selected digest while preserving the original verified collection and item digests. Cross-language producer/consumer fixtures cover0/1/2 items, reordered/dropped/duplicated/tampered items, altered selection/proof, later-version exclusion, clipped projections and frozen restore, with no per-item fetch. Collection bytes count within the existing180000-byte S9 response bound; bounded projections/proof references cannot add hidden full reports or chains.

For ordinary sources `producerFetchedAt` maps only the producer's temporal_metadata.fetched_at; for S9 the upstream fetch clocks remain on its items and the collection producer clock can be null as above. `researchCapturedAt` records the actual first research HTTP capture, never source observation/availability; it is not a field in the producer integrity input and is never substituted during producer hash reconstruction. Research receipt_metadata includes both named clocks, freezes them on restore and excludes any legacy fetchedAt alias. Producer/API transport remains fetched_at (not a consumer capture alias). Fixtures deliberately use different producer-fetch and research-capture dates and prove neither affects the other's digest domain or retroactively establishes availability.

## Risks

The strict replay policy will expose previously hidden unsupported sources; the user sees explicit unknowns, not fabricated history. Two extra evidence types can increase latency/context size; request, payload and model-input limits are tested. Old frozen sessions lack receipt metadata; they remain readable as historical artifacts but cannot be promoted into current evidence. Browser mocks can miss backend defects; separate stocks API tests and shared fixtures prove the provider contract, and the owner posts deployed-site checks after staging deployment.
