# Contract sync for the two retired stocks watchlist write routes (stage B)

## Problem

Stocks PR 1937 (FEAT-INSIGHT-001 stage B, `docs/superpowers/specs/2026-11-14-feat-insight-001-watchlist-write-routes-410-r2.md`
in stocks) merged on 2026-11-17 as `6ee71e5f`. `POST /api/insights/watchlist/add` and
`DELETE /api/insights/watchlist/{ticker}` now answer 410 and write nothing, and stocks' `platform/api/openapi.json`
declares that: both operations carry `deprecated: true`, the description `Retired (FEAT-INSIGHT-001 stage B): answers
410 and writes nothing.` and a 410 response.

Solyra Rule 6 binds the two repositories: `npm run contract:check` (CI and `docs-audit.mjs`) reads stocks main and has
been red since that merge. Measured on 2026-11-17 against stocks `6ee71e5f` (`platform/api/openapi.json` blob
`112dcf4e6c335122180d130c96430632cf353569`, SHA-256 `84aa792ab63b36f5a111037909edf2118487bcc9032428774acca81ce585757f`):
`contract:check` reports the vendored snapshot stale with exactly two operations changed, these two. A sync from that
file changes 12 lines of `tests/fixtures/stocks-openapi.json` and 31 of `src/types/stocksOpenApi.gen.d.ts`, all inside
the two operations; `src/mocks/contract.test.ts` passes (15 tests) and `tsc -b` is clean on the result.

The v3 user-watchlist spec (`2026-11-14-feat-insight-001-user-watchlist-v3.md`) foresaw this sync in its design
("later the two 410 declarations of stage B") but none of its `done_when` items holds it, and its plan is done, so no
open solyra change carries it.

## Non-goals

- No change to any screen, hook, mock, request or test. Solyra main requests neither operation since solyra #341
  (b4b37022), so no source reads the new declarations.
- No hand edit of either generated file.
- No change to the v3 spec or to stocks.

## Approaches considered

1. Leave `contract:check` red until the next feature PR happens to sync: rejected, every solyra PR's CI fails on it
   meanwhile (Rule 6).
2. Carry the sync in a later FEAT-ADMIN-001 change (the default watchlist editor rewrites the same 410 description):
   rejected, that change is not approved or scheduled, and the check is red now.
3. A standalone sync under FEAT-INSIGHT-001, which owns stage B: chosen, the same shape as the FEAT-CICD-001 ping sync
   (spec PR 322, sync PR 323) and the FEAT-CHART-001 similar-setups sync.

## Design

- Branch `fix/feat-insight-001-stage-b-contract-sync`, opened after this spec merges, with its plan in the same PR as
  PR 323 carried its plan.
- `npm run contract:sync` from stocks main writes both files. The plan records the source pin (stocks commit, blob and
  SHA-256 of the fetched `openapi.json`) and the SHA-256 of both written files, as the market-hours and ping plans do.
- If stocks main changes another operation's declaration before this merges, `contract:sync` brings that change too,
  and `done_when` item 1 then refuses the PR: the sync is redone with a spec that covers the extra change, rather than
  folding it in here.

Capacity: n/a, no workload. One fetch of one file at sync time.

## Risks

- Stocks main changes another declaration first: item 1's diff check refuses a sync that changes anything but the two
  operations, and item 2 keeps the check honest at merge time.
- A solyra source still requested a retired operation: item 3's search would find it; it finds nothing on solyra main
  `7fbc864`.
