# Similar setups: show the realized win share honestly and sync the contract

## Authority

The owner asked on 2026-11-13 for this sync and the two label changes. This spec is a draft: it takes
effect only when the owner approves it, and only the owner moves its `status` to approved.

## Problem

Stocks PR 1833 (FEAT-SIGNAL-001, merged 2026-11-12 UTC, stocks main `b2d101a`) changed
`GET /api/signals/{ticker}/similar`:

- `pct_profitable` is now the realized win share: the share of matched rows whose fixed-exit result
  (rule `next-open-20m-1c-v1`) is above 0, among the matched rows that have one. It is null when none has
  one, never 0.
- New `realized_count`: the number of matched rows with a realized result, the denominator above. Rows
  outside regular hours, rows whose exit would fall after the close and rows written before the rule
  existed have none, so `realized_count` is often well below `count`.
- New `pct_moved_in_favor`: the old best-of-20-closes share, under an honest name.
- `avg_return_5min` and `avg_return_20min` keep their values but are now described as the best close
  within the window, not a return.

Solyra Rule 6 ties the vendored snapshot to stocks main, so `npm run contract:check` has been red on
solyra main since that merge (main CI on `62e86d2` and `546a371`). A sync from stocks main changes only
the `SimilarStats` schema; locally, after it, `tsc -b`, all 81 vitest files (1,766 tests) and
`contract:check` pass.

Two readers now mislead without a code change:

1. The Similar setups card (CHARTS-06, also shown on Insights through `MarketSignals`) puts
   `% profitable` beside `Matches` with no denominator. With 240 matches and 2 realized, a 50% tile reads
   as 120 winners.
2. The Insights evidence summary (`supabase/functions/insights-research/index.ts`, the `summarize`
   similar_setups line) tells the model `avg 20-min return`, which stocks now defines as a best case.

## Non-goals

- No `% moved in favor` tile. Stocks is testing whether a per-ticker hold should replace the fixed
  20-bar exit; the card adds that figure once the rule settles.
- No change to the `+5 min` and `+20 min` match columns: they are per-row best closes, labelled by their
  window, and unchanged in stocks.
- No change in stocks, and no hand edit of either generated file.

## Approaches considered

1. Sync only: rejected. CI turns green but the tile and the summary keep reading as before.
2. Sync and add `% moved in favor` beside `% profitable`: deferred, see Non-goals.
3. Chosen: sync, show the realized count under the tile, and relabel the summary's 20-bar figure.

## Design

- `npm run contract:sync` from stocks main writes both generated files. The plan pins the stocks commit,
  the blob and the SHA-256 of the fetched `openapi.json`, and the SHA-256 of both written files.
- `SimilarStats` (`src/hooks/useSimilarSetups.ts`) gains `realized_count?: number | null` and
  `pct_moved_in_favor?: number | null`; `MOCK_SIMILAR_SETUPS` carries realistic values for both
  (realized share near one half, moved-in-favor share near the old 85%).
- `SimilarSetupsCard`'s `% profitable` tile keeps its label and value format and adds a muted second line:
  `of N realized` when `realized_count` is a number above 0, `none realized yet` when it is 0. A
  missing `realized_count` adds no line. No new copy names a number of minutes, so a per-ticker hold in
  stocks needs no relabel here; a changed field shape is caught by `contract:check`.
- The Insights summary reads `X% profitable of N realized` (or `X% profitable` with no count) and
  `avg best move Y%` in place of `avg 20-min return Y%`.
- CHARTS-06 in `docs/UI-SCREENS.md` describes the tile as above.
- Branch `fix/feat-chart-001-similar-setups-realized`, opened after this spec merges.

Capacity: n/a, no new request or polling. One fetch of one file at sync time.

## Risks

- Stocks changes the endpoint again before this merges: `contract:check` on the head (done_when item 2)
  fails, and the sync is re-run from stocks main.
- The Insights summary change reaches users only after a Lovable publish, like the card.
