# Retire the Lovable research workspace and remove Supabase from solyra

## Authority and status

Written 2026-11-14 from the owner's directive of 2026-11-13 ("Solyra doesn't use Supabase, only GCP.
Stocks either.") and 2026-11-14 ("Why is Supabase showing in solyra? Nothing should be Supabase."),
recorded as solyra #339. The owner approves it by merging the PR that adds it, under the standing
instruction that this work is driven to completion; the reversal path is a superseding spec.

## Problem

One feature in solyra runs on Supabase: the research workspace Lovable generated behind the two nav
items `/insights-lovable` (Insights Lab) and `/ai-insights-lovable` (AI Insights Lab). Its browser hook
`src/hooks/useInsightsLovable.ts` posts to a Supabase edge function
(`supabase/functions/insights-research/index.ts`, URL from `src/lib/researchServiceConfig.ts`) that
verifies the Firebase token through stocks `/api/me`, stores sessions, messages, runs and sources in
four `insight_research_*` tables of Supabase project `hajmcfkqmtgidstpggrh`, and calls the Lovable AI
gateway with a Lovable API key. Lovable's generated client lives in `src/integrations/supabase/` and
`@supabase/supabase-js` is a dependency. Nothing else in solyra touches Supabase: the watchlist,
charts, options, signals, journal and the regular `/insights` page call the stocks API on Cloud Run,
and stocks has no Supabase code at all.

The owner's architecture is GCP only. A second backend with its own auth path, its own data store and
its own model gateway is a second system to secure, pay for and keep consistent, and it was never a
decision; it was Lovable's default. The research workspace itself was never promoted past the LAB badge.

## Non-goals

- No rebuild of the research workspace. If the owner wants question-first research sessions back,
  that is a new spec on the stocks API and Cloud SQL (tables in `gcp/schema.sql`, session and message
  routes, the model call through the stocks agents stack), not part of this change.
- No change to the regular `/insights` page or to any other route; `WatchlistPanel`, `TickerCombobox`,
  `useWatchlist`, `useInsights` and the other modules the Lab pages shared with `/insights` stay.
- No change to the frozen specs and plans under `docs/superpowers/` that mention Supabase as history
  (the 2026-11-13 watchlist specs and plans, the 2026-10-12 research-evidence spec, the 2026-10-27
  hermetic baseline spec, the 2026-11-01 account-transitions spec). An approved spec does not change
  in place; their Supabase clauses describe code this change deletes.
- No Supabase project administration from the repo. Disconnecting the Lovable integration and pausing
  or deleting the project are the owner's steps (see Outside the repo).

## Design

### Removal inventory

Reachability from `src/main.tsx` with the two Lab routes removed, measured on main at c738cb34 and
abc57b44, leaves these production files unreachable, and they are deleted:
`src/routes/InsightsLovablePage.tsx`, `src/routes/AiInsightsLovablePage.tsx`,
`src/hooks/useInsightsLovable.ts`, `src/types/insightsLovable.ts`, `src/lib/researchServiceConfig.ts`,
`src/components/insights/LiveQuoteBox.tsx`, `src/components/insights/ResearchCandleChart.tsx`,
`src/components/insights/redesign/MarketSignals.tsx`, `src/components/insights/redesign/Panels.tsx`,
`src/components/insights/redesign/decision.ts`, and `src/integrations/supabase/client.ts`,
`previewAuthStorage.ts`, `types.ts`. With them go the whole `supabase/` directory (`config.toml`,
`functions/insights-research/index.ts`, `functions/_shared/cron-auth.ts`), the two routes in
`src/App.tsx` (lines 24, 25, 100, 101 today) and the two entries in
`src/components/layout/navConfig.ts` (lines 73, 74), the Vitest files that test only deleted modules
(the ten named in done_when item 2; `researchEvidence.test.ts` and
`researchSourceContract.regression.test.ts` read the edge function's source), the Playwright folders
`tests/insights-lovable/` and `tests/ai-insights-lovable/`, and the two `.lovable/plan` notes about
deploying the research function. Every other file reachable from the Lab pages is also reachable from
`/insights`, the dashboard, the journal or the header and stays untouched.

### Guard

`src/lib/noSupabase.test.ts` lists the tracked files (`git ls-files`), reads each text file and
asserts that every file containing `supabase` (case-insensitive) lies under `docs/superpowers/`. The
allow-list is the directory, not file names, so a new spec may still describe history while any new
dependency, client, URL, key, project id or function reference under `src/`, `tests/`, `scripts/`,
`.lovable/`, the manifests or the Playwright config fails the run. The test prints the offending paths.

### Retired routes

`tests/shared/retired-lab-routes.spec.ts` (hermetic, `mockCommon`, the suite's signed-in auth state)
visits `/insights-lovable` and `/ai-insights-lovable` and asserts each shows the view `App.tsx` renders
for an unknown path, and that the navigation offers neither label and no `LAB` badge. It saves
`page.screenshot` of both paths and of the navigation to `testInfo.outputPath`, which is the before and
after evidence the PR carries (the before state is the Lab page itself, captured once from main).

### Dependencies, lockfiles and config

`@supabase/supabase-js` leaves `package.json`; `npm install` regenerates `package-lock.json` and
`bun install --lockfile-only` regenerates `bun.lock` (Lovable installs with bun); `npm ci` from the
result is the proof. `playwright.config.ts` drops the `VITE_SUPABASE_URL` and
`VITE_SUPABASE_PUBLISHABLE_KEY` entries it set so local research requests hit a mock; the mock has no
consumer once the hook is gone. `src/lib/authGate.test.ts` keeps its scan that nothing under `src/`
removes or clears a stored value and drops its exemption for `previewAuthStorage.ts`.

### Catalog

The FEAT-INSIGHT-001 row of `docs/product/02-FEATURE-CATALOG.md` lists `/insights` alone under UI,
`/api/insights` alone under Backend, `insight_reports` and `insight_runs` under Data, and its Status,
Last reviewed and PRs columns are updated. No other row changes.

## Outside the repo (owner steps, after the merge)

1. Disconnect Supabase from the Lovable project (project settings, integrations). While the
   integration stays connected, the editor can regenerate `src/integrations/supabase/client.ts` and
   `types.ts` on its next sync; the guard test would then fail CI on the connected branch, which is
   the right alarm, but the disconnect prevents it.
2. Pause or delete Supabase project `hajmcfkqmtgidstpggrh`. Its four `insight_research_*` tables hold
   the research sessions written so far; export them first if any are wanted. Nothing in solyra or
   stocks reads them after this change.
3. Remove the Lovable AI gateway key and the cron secret the edge function used; no code reads them.

## Interactions

- The v3 watchlist plan (`docs/superpowers/plans/2026-11-14-feat-insight-001-user-watchlist-v3.md`,
  Task 7) asserts `supabase/functions` holds only `_shared` and `insights-research`. Once this change
  lands that directory does not exist; the v3 implementer edits Task 7 on the v3 branch (a plan is
  editable on its own branch) to assert the directory is absent, and `src/lib/noSupabase.test.ts`
  already covers the files v3 adds. Task 6 of the same plan cites
  `tests/ai-insights-lovable/workspace-integration.spec.ts` for its signed-in pattern; the pattern (the
  auth storage state and `mockCommon`) is the suite's, not that file's, and the implementer takes it
  from `tests/insights/` after this change.
- The 2026-10-27 hermetic baseline spec's clause that preserves the `__e2e_research__` loopback mock
  described the research hook's only safe local target; with the hook gone the clause has nothing to
  protect and the Playwright config no longer sets the variables.

## Risks

- A Lovable sync re-adding the generated client after the merge. Mitigation: the owner's disconnect
  step, and the guard test, which fails on the connected branch if it happens.
- A shared module misclassified as Lab-only. Mitigation: the inventory is the measured reachability
  from `src/main.tsx`, `tsc -b` and `npm run build` fail on any dangling import, and the hermetic
  suite exercises every remaining route.
- `bun.lock` drift if bun is unavailable where the change is made. Mitigation: bun 1.4.4 is installed
  in the session that implements this; `npm ci` proves the npm lockfile, and Lovable's own `bun install`
  tolerates a lockfile regenerated by the same bun major.

## Decisions (owner, 2026-11-13 and 2026-11-14)

1. Solyra and stocks run on GCP only; nothing should be Supabase.
2. The research workspace is retired rather than re-homed now; a rebuild on the stocks API is a
   separate spec if wanted.
