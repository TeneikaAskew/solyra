# Contract sync for the retired API service's ping description

## Problem

Stocks PR 1384 (FEAT-DEPLOY-001, `docs/superpowers/specs/2026-10-11-feat-deploy-001-retired-service-leftovers.md`
in stocks) rewrites the second paragraph of the `GET /api/earnings/health/ping` docstring in
`platform/api/routers/earnings.py`, because it still names `solyra-api-prod`, the service retired on
2026-10-10 (stocks PR 1366), as sitting behind IAP. The description is part of stocks'
`platform/api/openapi.json`, which solyra vendors as `tests/fixtures/stocks-openapi.json` and turns into
`src/types/stocksOpenApi.gen.d.ts`.

Solyra Rule 6 binds the two repositories: once that change is on stocks main, `npm run contract:check`
(CI and `docs-audit.mjs`) reads it and stays red until the vendored snapshot and the generated types follow.
On 2026-11-09 solyra main's snapshot equals stocks main's `openapi.json` exactly (compared as parsed JSON),
and a sync from the stocks PR head (2215223a) changes one line of the snapshot and three lines of the
generated types, all inside that description.

The approved FEAT-AUTH-001 spec `2026-10-11-feat-auth-001-confirm-on-return.md` planned to carry this sync
inside the confirm-on-return change. Its implementation PR (solyra#278) was closed on 2026-11-07 and no open
solyra PR carries the sync, so the stocks change has no partner to merge after it.

## Non-goals

- No change to any screen, hook, mock, request or test: no solyra source reads this description.
- No change to the confirm-on-return spec. Its sync bullet becomes a no-op: once this lands, a later
  `contract:sync` from stocks main finds nothing to change for this description.
- No hand edit of either generated file.

## Approaches considered

1. Carry the sync in a FEAT-AUTH-001 PR under the confirm-on-return spec: rejected, that spec's other
   `done_when` items (the confirm-on-return behaviour) are not this change, so such a PR could never close.
2. Leave solyra red after stocks PR 1384 merges and sync later: rejected, it breaks `contract:check` on main
   for an unbounded time (Rule 6).
3. A standalone sync under FEAT-CICD-001, which owns the contract check: chosen, the same shape as the
   FEAT-ADMIN-001 market-hours sync (specs PR 316, fix PR 317).

## Design

- Branch `fix/feat-cicd-001-ping-contract-sync`, opened after this spec merges, as a draft first.
- `STOCKS_OPENAPI_REF=feature/feat-deploy-001-retired-service-leftovers npm run contract:sync` writes both
  files. Its `contract:check` against stocks main is red until stocks PR 1384 merges; stocks PR 1384 links
  this PR in its description and states the order.
- Merge order: stocks PR 1384 merges; this PR's CI is re-run, `contract:check` passes against stocks main;
  it merges with current-head review and owner authorization.
- The plan records the source pin (stocks commit, blob, SHA-256 of the fetched `openapi.json`) and the
  SHA-256 of both written files, as the market-hours plan does.

Capacity: n/a, no workload. One fetch of one file at sync time.

## Risks

- Stocks PR 1384's head moves after the sync: `contract:check` against stocks main catches any further
  difference once it merges (`done_when` item 2), and the sync is re-run then.
- The stocks PR changes another described field before merging: item 1's diff check refuses a sync that
  changes anything but this description.
