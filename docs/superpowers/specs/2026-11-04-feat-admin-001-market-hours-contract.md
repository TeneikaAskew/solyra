# Market-hours contract sync for the shared NYSE calendar

## Contract

Dependency: stocks spec `docs/superpowers/specs/2026-10-19-feat-data-001-shared-market-calendar.md`
and its PR 1546. That PR adds two required fields to `GET /api/config/market-hours`
(`MarketHoursResponse`): `holidays`, the NYSE full-day closures of the current and next
Eastern year as ISO dates, and `early_closes`, the half-day sessions of the same window
as `{date, close}` with `close` in `HH:MM` Eastern. It also adds an optional `detail`
string to `FreshnessRow`. `holidays_2026` is kept and is now filled from the same
calendar, so it gains 2026-06-19 and no longer lists 2026-11-27, which is a half day.

Solyra Rule 6 binds the two repositories: once the stocks change is on main, solyra's
`contract:check` reads it and stays red until the vendored snapshot, the generated types
and the mock that the contract test validates follow it.

## Scope and limits

Only `tests/fixtures/stocks-openapi.json`, `src/types/stocksOpenApi.gen.d.ts` (both from
`npm run contract:sync`, never hand-edited), `src/hooks/useConfig.ts` (`MarketHours`),
`src/mocks/common.ts` (`MOCK_MARKET_HOURS`), the FEAT-ADMIN-001 catalog row and the plan.
No consumer moves from `holidays_2026` to `holidays` here and no screen changes: that is
stocks' Spec C, which decides the replay picker's walk-back. No new request, polling,
fallback or default value; the mock values are the real 2026 and 2027 NYSE dates.

## Close-out

Merge after stocks PR 1546 is on main, with current-head review and checks. The deployed
API's values are recorded on stocks PR 1546; this change has no deployed behaviour of its
own to verify, because no screen reads the new fields yet.
